# 中国象棋 · 人机对战

中文 · [English](README.md)

纯静态网页游戏,无构建步骤、无依赖、无音频素材文件(音效全部实时合成)。

## 运行

直接双击 `index.html` 就能玩,不需要服务器,也不需要装任何东西。

脚本是普通 `<script>`(不是 ES module),因为浏览器在 `file://` 下会拒绝加载模块脚本和
module Worker —— 那样就必须架一个本地服务器才能跑。现在整个文件夹拷到任何地方、
用任何浏览器打开 `index.html` 都可以。放服务器上跑也一样。

电脑方的 WASM 也是这么带走的:`.wasm` 内联成 `engine/wasm64.js` 里的一段 base64
(707,854 B,gzip 后 255,173 B),因为 `file://` 下 `fetch` 和 XHR 同样被禁。代价是首屏多
解析这 700 KB 文本;换来的是"一个文件夹、什么都不用下载"。

## 玩法

- 先点自己的棋子,棋盘上会标出这一子当前所有合法落点(实心点是空点,套环是吃子);
  再点落点走子。鼠标悬停会显示半透明的预览。
- 点另一个自己的子是换选,不弹错误;点去不了的地方会取消选中并提示。
- 右侧面板可切换难度(1~5 档)和你执红先手还是执黑后手。
- 悔棋一次撤销你和对方各一手;重新开始随时可用,胜负之后也能悔棋继续。
- 切换执子颜色会开始新局;难度可以中途改,对方正在思考的话立刻按新档位重想。
- 走棋记录按中文记谱(炮二平五 / 砲2进7),最后一手高亮;下面四个按钮把棋谱导出成 txt、
  导入回来,或者复制到系统剪切板 / 从剪切板粘回来。

## 五档难度

电脑方是 `engine/` 里那份 Pikafish-HCE 编译成的单线程 WASM。五档只动两个旋钮:引擎自己的
Skill Level(棋力弱化)和每手的思考时限。

下面这张表是按**出货代码的下发方式**(逐层 `go depth`,见下一节)实测的:对手 ElephantEye 3.31
同样限 200 毫秒,20 盘、固定 8 个开局轮换先后手、零非法着、零超时。

| 档 | Skill Level | 时限 | 实测每手 | 平均层数 | 得分率 |
|---|---|---|---|---|---|
| 1 | 5 | 200 毫秒 | 276 毫秒 | 18.0 | 13%(0-5-15) |
| 2 | 8 | 200 毫秒 | 278 毫秒 | 15.9 | 30%(0-12-8) |
| 3 | 20 | 200 毫秒 | 316 毫秒 | 24.1 | 73%(9-11-0) |
| 4 | 20 | 600 毫秒 | 729 毫秒 | 34.4 | 83%(13-7-0) |
| 5 | 20 | 1000 毫秒 | 1000 毫秒 | 36.3 | 80%(12-8-0) |

实测每手都比时限高,因为最后一层一定跑完才收手、不能中途掐:时限是"要不要再起下一层"的
截止线,不是这一手的上限。

20 盘的样本标准误约 ±11%,所以站得住的是"1 档明显最弱、2 档次之、3 档往上都是强手",而不是
相邻两档的精确排名。**4 和 5 在这个对手面前分不开**(83% 与 80% 在噪声之内):对手只限
200 毫秒,3/4/5 档已经顶到它能给出的天花板,再往深走赢不到更多。真要 4、5 档拉开,唯一的杠杆
是加时限(比如 600 / 1500 毫秒),不是调别的。

同一套参数在接 WASM 之前用 `go movetime` 测过,对手分别换成 ElephantEye 和 Fairy-Stockfish 1.1
(也各限 200 毫秒),得 0/10/65/70/80% 和 0/8/63/78/85% —— 两个互不相关的引擎上阶梯都单调,
这是"档位本身成立、不是对某个对手的特化"的依据。换成逐层下发后底部两档的间距反而更开
(13/30 而不是 0/10),因为每手实际多花了七八十毫秒。

Skill Level 是引擎内部的弱化机制,不是"少算几层":`level < 20` 就启用,在第 `1 + level` 层
从 MultiPV 前几名里带噪声挑一手(S5 在第 6 层挑、S8 在第 9 层挑),层数没跑到也会在收尾时
无条件注入一次噪声。所以 1、2 档算得和 3 档一样快,只是**故意挑次好的一手** —— 送子就是这么
来的。3/4/5 档不掺随机,只比谁算得深。

## 引擎是怎么接进来的

三个约束决定了这里的写法;编译链和重新编译的步骤在 [engine/README.md](engine/README.md)。

1. **`.wasm` 内联成 base64。** 双击 `index.html` 就得能玩,而 `file://` 下 Chrome/Edge 禁
   `fetch` 和 XHR,`.wasm` 按 URL 取不到。`engine/wasm64.js` 就是 `pikafish-hce.wasm` 的
   base64(530,804 B → 707,854 B 文本,gzip 后 255,173 B),经 emscripten 的 `instantiateWasm`
   注进去。这是这次改动唯一的体积代价。
2. **一次思考按层下发。** 这个构建只在读命令那一处让出,一次 `go` 从发起到 `bestmove` 全程
   占死主线程 —— `go movetime 1000` 就是冻一秒,思考时的实时读数一次都不会刷。所以
   `js/engine.js` 下发 `go depth 1`、`2`、`3`……,每层之间让出一个宏任务(`setTimeout(0)`),
   浏览器才画得了一帧、点击才不会被吞。停止条件是累计墙钟超过档位时限;每层另加 40 万节点的
   硬上限,给"主线程一次卡多久"兜底 —— 层与层的时间极不均匀,多数层 1~3 毫秒,少数层几百毫秒
   (分布见下面"界面怎么保持响应"那张实测表)。不要改成反复 `go nodes N`:实测每片都是独立搜索,深度在 13~17 之间乱跳、
   bestmove 每片换一个,4、5 档会退化成 0.1 秒的棋力。
3. **局面靠 FEN 交换。** `rules.js` 的 `fen()` 写标准象棋 FEN(行序按棋盘原样、file 0 → `a`、
   大写红子),引擎回的 ICCS 着法用 `r = 9 - 数字` 翻回我们的坐标。这条接缝拿引擎自己的
   `go perft` 对过:同一局面下 js 与引擎的 perft1/perft2 节点数,在开局和 12 手随机对局里的
   非对称局面上全部相等。

引擎起不来时状态栏会明说(`引擎异常:…`),不会静默卡住。

## 界面怎么保持响应

引擎跑在主线程上,但按层下发让每一层之间都有一次让出(见上)。单层耗时是实测的 —— 出货的下发
方式、同一批开局对 ElephantEye,在 Node 里跑,不含浏览器那次让出:

| 档时限 | 每手层数 | 单层中位 | p90 | p99 | 单层最长 | 一手总时长 |
|---|---|---|---|---|---|---|
| 200 ms | 24.7(中位 19) | 1 ms | 20 ms | 299 ms | 510 ms | 335 ms |
| 600 ms | 39.8(中位 24) | 2 ms | 33 ms | 340 ms | 443 ms | 695 ms |
| 1000 ms | 55.4(中位 24) | 3 ms | 26 ms | 416 ms | 470 ms | 1036 ms |

多数层只有 1~3 毫秒,时间几乎全压在最后几层:200 ms 档最后一层占这一手的 62%,1000 ms 档占
29%。40 万节点的上限实测把最长的一层压在 0.5 秒内,但它是软的 —— 引擎每 390 次根着法才查一次
节点数,所以会超一点。浏览器里每层还要多一次 `setTimeout(0)`,嵌套定时器被钳到至少 4 毫秒。
实测 5 档一手 1.20 秒里读数刷了 3 次(262 / 514 / 1203 毫秒),最长的一次卡顿就是那半秒,动画
和点击在那半秒里会钝一下,其余时间一切正常。

悔棋、重开、换难度把当前这一局标记为作废:正在跑的那一层跑完就收手,**绝不再下发下一条 `go`**
—— 否则会和紧接着开始的新搜索抢同一条输出队列。回调解包时再核对一次令牌,所以在对方思考时
重开新局不会落下一颗"幽灵棋子"。

对方思考时,状态栏下面那两行每 200 毫秒刷一次:上一行写已跑完的层数和已用时间,下一行写已搜索的
局面数,例如 `电脑 · 6 层 · 0.4 秒` / `1,234,567 个局面`;这一手落定后同样两行换成它的结论。
两处报的都是各层 `info depth` 里最大的那个 —— 只有整层跑完才会打 `info`。这个数能高到 245,
那不是假读数:245 是迭代加深的 `MAX_PLY` 封顶,而已证杀的局面里超过杀距的每一层只要 1~4 毫秒,
200 毫秒的预算能一路刷到 200 多层。读数偶尔比结论少一层只是 200 毫秒定时器的滞后。

两行都是固定高度、空着也占位,而且不换行(超了就截断)。这样"思考中"和"落定后"占的高度一样,
读数出现、消失也不会把下面整栏顶得上下跳。刷新用 `setTimeout` 链而不是 `requestAnimationFrame`
—— 后台标签页里 rAF 会被冻住。

## 规则说明

- 蹩马腿、塞象眼、象与兵不过河、士帅不出九宫、炮翻山吃子,都在着法生成阶段处理。
- **白脸将**(两将同列且中间无子)不需要特判:它等价于"走完之后自己的将被对方将吃掉",
  而将/帅沿竖线的远程攻击写在 `attacked()` 里,所以自动被合法性过滤挡掉。
- **困毙与将死同样判负** —— 象棋里无子可走就是输,不算和。
- **三次重复局面判和**。这是简化实现:完整的亚洲规则长将、长捉判负不在范围内,
  所以理论上存在"一方长将却被判和"的局面。
- 没有 60 回合自然限着、没有摸子走子、没有棋钟。

## 记谱

侧栏走棋记录用中文记谱。线路从**各自一方**的右手边数起,所以红方一路在屏幕最右、
黑方 1 路在屏幕最左。红方用 `一二三四五六七八九`,黑方用 `1…9`。

格式是 `兵种 + 起点线路 + 动作 + 落点`:

- `炮二平五` —— 二路炮横移到五路。
- `马八进七` —— 八路马向前跳到七路。马、象、士是斜走的,步数永远是 2 没有信息量,
  所以它们的落点写线路而不是写步数。
- `兵七进一` —— 七路兵前进一步,这一步是步数。

歧义按竞赛规则是**位置性**的:同一种子有两只以上落在同一条竖线上时,线路号分不开,
一律改用 `前` / `后`(三只时 `前` / `中` / `后`),而且用了前/后就不再标线路 ——
`前马进七`、`中兵进一`。两只同种兵在不同线路上时,写法本身带线路号,天然不歧义。

记谱必须在 `make` **之前**算:它看的是"走之前"的盘面,走完之后同线那只子可能就数错了。
所以算好之后存进 history,悔棋缩短它、重开清空它。

## 棋谱的导入导出

走棋记录下面四个按钮:导入、导出、复制、粘贴。

导出的文本按回合一行,`1. 炮二平五 馬2进3`。文件名是 `xq_年-月-日_时-分-秒.txt`。
文件开头写一个 UTF-8 BOM —— Windows 记事本没有它就按本地编码猜,中文棋谱直接成乱码。

导入**不写记谱解析器**:拿每一手去比对当前局面每个合法着法生成的记谱,相等就是它。
记谱在给定局面下本来就是唯一的(同线的歧义已经由前/中/后消掉了),所以匹配得上那一手
必然是那一手,匹配不上就是这局走到这儿不通,状态栏写 `第 N 手读不通:那一手`。
这么一来分隔符也不用定死:换行、空格、中英文逗号、分号都算分隔,行首的 `1.` 这类序号
会被剥掉,所以手写一段、从别处粘一段都能读回来。

先在临时局面里走完,走通了才换掉当前对局 —— 半途报错不会把棋盘留在中间状态。
导入后轮到电脑就立刻开始思考,导入的局面已经终局就直接结算。当前有对局在进行时
会先确认一次(文件和粘贴两条路都拦)。

复制和粘贴走 `navigator.clipboard`。异步剪切板 API 要安全上下文,`file://` 下不一定给用,
浏览器也常常拒绝读,所以两边各留一条退路:写失败退回 `execCommand('copy')`,读不到就聚焦
一个看不见的输入框、提示用户自己按 `Ctrl+V`,由 `paste` 事件接手。

## 缩放

棋盘最小 314 × 348 像素(格距触底在 34 像素,再小棋子上的汉字就糊了)。比这更窄的窗口里
棋盘区域出滚动条,而不是把棋盘压扁。

棋盘**不是正方形**:9 条竖线 × 10 条横线,加上四周外框留白之后是 9.24 × 10.24 个格距,
所以 `layout()` 要按两个方向分别求格距再取小值 —— 按正方形算的话,窄窗口里棋盘会横向溢出,
宽窗口里上下留一大片空。可用空间变大时棋盘取棋盘区域宽高中较小值的 94% 等比放大,
棋子半径、字号、线宽、选中环、落点、光晕全部由这一个格距推导,所以棋盘和棋子始终同步缩放。

`ResizeObserver` 的回调用一个 `requestAnimationFrame` 去抖,拖动窗口时每帧只重排一次。
canvas 按 `devicePixelRatio` 放大后备分辨率(上限 2.5),高分屏上线和字不发虚。

## 主题

标题栏右侧的太阳/月亮按钮切换暗色和亮色;图标表示的是"点下去会变成什么"。

两套配色都只是数据:界面走 CSS 自定义属性(`html[data-theme="light"]` 覆盖一整套 token),
棋盘走 `js/render.js` 顶部的 `PALETTES`。换主题就是重烤一次缓存层和棋子精灵
(`Renderer.setTheme`),不重量尺寸也不改 canvas 大小。参与动画的颜色在调色板里存成
`r,g,b` 三元组,alpha 由动画曲线给,所以换主题不用动任何一条动画公式。

亮色下棋盘本身也换成浅枫木,跟着改的有三处:棋子边缘的暗色描边加深(浅底上只靠投影撑不出
立体感),河界文字翻成深色,胜负光带的混合模式从 `lighter` 换成 `source-over`
—— `lighter` 在浅底上会直接过曝成白,光带和粒子全都看不见。所以混合模式本身也是一个 token。

没手动选过主题时跟着系统的 `prefers-color-scheme`,选过之后就固定下来不再跟。
首帧不会闪一下深色:`<head>` 里有一段内联脚本,在样式表之前就把 `data-theme` 定好。

## 音效

没有任何音频文件。每个音效都是在该响的那一刻用振荡器和噪声现搭的,这正是整个游戏能保持"一个
文件夹、什么都不用下载"的原因 —— 也意味着 `file://` 下和 http 下听到的完全一样。

### 一张图,第一次点击时搭好

浏览器在用户操作之前拒绝启动 `AudioContext`,所以第一次 `pointerdown` 或 `keydown` 之前什么都
不存在(两个监听都挂在 capture 阶段,解锁它的那次点击轮到处理时,上下文已经在跑了)。那一次调用
搭好整张常驻的图:

```
sources ─→ master gain ─→ destination
        └→ wet send ─→ convolver ─→ master gain
```

有两块 buffer 是在那一刻程序生成的,因为没东西可加载:

- **冲激响应**是 1.4 秒的立体声白噪声乘以 `(1 − t)^2.6`,右声道再乘 0.8。这是一条衰减曲线,
  不是某个房间的实测 —— 每个音效因此带一点短而软的尾巴,却不需要混响素材。
- **噪声 buffer** 是 0.25 秒白噪声,每次落子、吃子都复用它。

其余节点都是每个音效现建、放完就回收。

### 一个原语:`tone()`

几乎所有音效都是同一个形状 —— 振荡器接一个增益,十几毫秒内爬升、在音符长度内降回去,再按需分
一路给混响。用指数斜坡而不是线性斜坡,因为响度本来就是对数感知的;指数斜坡到不了 0,所以底是
`0.0001`。排期一律按绝对的 `ctx.currentTime`,所以胜利那段琶音是一次调用排下十几个振荡器然后
立刻返回。

### 各个音效

| 音效 | 配方 |
|---|---|
| 选中 | 3200 Hz 带通噪声的一记轻点 + 1180 Hz 三角波,50 毫秒 |
| 落子 | 噪声过一路 bandpass,红子 1900 Hz / 黑子 1500 Hz,Q 1.1 —— 这是"嗒";底下垫 150 Hz 正弦的闷响和 78 Hz 三角波的腔体 —— 这是棋子落到板上 |
| 吃子 | 先一记 2600 Hz 的脆响,45 毫秒后补一记 900 Hz、Q 2.2 更钝的;再压 210 Hz 方波和 66 Hz 三角波 260 毫秒 |
| 将军 | 两声上行方波 880 → 1320 Hz(0.12 秒、0.14 秒),底下垫 196 Hz 三角波 |
| 走不通 | 两个方波,150 Hz 然后 112 Hz —— 方波是这套音效里故意留下的钝而难听的音色 |
| 悔棋 | 一个三角波从 700 Hz 滑到 280 Hz,160 毫秒 |
| 胜 | 从 D5 到 D6 六级上行 587–659–784–880–1047–1175 Hz,每 110 毫秒一级,每级一个三角波加一个高八度正弦,底下压一条 1.5 秒的 D4 持续音,半秒后再进一个 A4 |
| 负 | A4–G4–E♭4–A♭3 每 170 毫秒一级,正弦,底下垫 110 Hz 三角波 |
| 和 | 两下 392 Hz 正弦,相隔 240 毫秒 |

落子那声"嗒"每次频率随机偏移 ±6%,闷响 ±5%,所以连着落十子不像把同一声循环十遍。红黑两色
亮度不同,眼睛离开棋盘也能听出是哪一方落的子。

### 音量和静音

主音量是 `音量^1.6 × 0.9` 而不是滑块的原始值:那个指数是一条粗略的感知曲线,滑块拉到中间才是
合适的响度,而不是几乎听不见。静音既把主音量置 0,又让每个音效在 `ready` 检查处直接退出 ——
上下文得存在、已启用、且真的在运行 —— 所以静音状态下根本不建任何音频节点。同一个检查还兜住了
"第一次手势之前就触发音效"这种情况:直接丢掉,不报错。

```
js/render.js      Canvas 绘制与动画,含两套调色板 PALETTES
js/sound.js       Web Audio 合成音效
engine/           Pikafish-HCE 编译成的单线程 WASM、它的 base64 内联产物、编译脚本
js/engine.js      引擎适配层:实例化、UCI 握手、逐层下发、ICCS 解码
js/ai.js          引擎宿主:同时只跑一手,取消与令牌核对
js/main.js        状态机与 UI 事件
js/search.js      接 WASM 之前那套 JS 搜索(迭代加深 Alpha-Beta + 静态搜索 + 置换表 +
                  空着裁剪 + 棋型评估)。仍在仓库里,但 index.html 不再加载它
```

脚本共用全局作用域(没有 `import`/`export`),所以 `index.html` 里的加载顺序不能乱:
`rules → notation → render → sound → 引擎 → ai → main`。
共用作用域也意味着不同文件的顶层名字不能撞,撞了是 SyntaxError 而不是警告。

只有偏好(主题、难度、执子、静音、音量)存进 `localStorage`,key 是 `xiangqi.prefs`。
部分浏览器在 `file://` 下限制 `localStorage`,所以读写都包在 `try/catch` 里:
存不了就退化成只在本次会话有效。

界面只有中文,没有多语言层。
